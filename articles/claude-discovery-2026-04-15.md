# Claude Code 今日の発見 — 2026-04-15

「ラップトップを閉じても動く」——昨日発表されたClaude Code Routinesが象徴するように、AIコーディングは「対話」から「バックグラウンド実行」のフェーズに入った。今日の発見は、その流れを裏付ける事例ばかりだ。

## Anthropic が Claude Code Routines を発表、夜中の2時にバグを直してPRを開く世界へ

4月14日、AnthropicはClaude Code Routinesの研究プレビューを公開した。これまでのClaude Codeは、ターミナルを開いている間だけ動くツールだった。Routinesはその制約を取り払う。スケジュール・API・GitHubイベントの3種類のトリガーで、クラウド上でClaudeが自律的にタスクを実行する。

たとえば「毎晩2時にLinearから最優先バグを取得し、修正を試み、draft PRを作成する」という設定が可能になる。朝起きたらPRが待っている、という開発体験だ。GitHub Triggerでは、PRのオープン時に社内チェックリストを自動適用したり、マージ後にドキュメントの整合性をチェックしたりできる。API Triggerを使えば、Datadogアラート発火時にトレースを解析し、最近のデプロイと照合してトリアージサマリを生成する——オンコール担当がPagerを見る前に。

YOMIKOの文脈で言えば、クライアントレポートの定期生成や、広告運用データの異常検知→Slack通知といったワークフローを、ノーコードで組める可能性がある。

[Claude Code Routines Guide](https://pasqualepillitteri.it/en/news/851/claude-code-routines-cloud-automation-guide)

## Stripe、1,370名のエンジニアにClaude Codeを展開——10週間の移行作業を4日で完了

Stripeは全社1,370名のエンジニアにClaude Codeを導入した。注目すべきは導入方法だ。Anthropicと共同で署名付きエンタープライズバイナリを開発し、npmの依存関係によるセキュリティ懸念を回避した。「ゼロコンフィグレーション」で各開発者のマシンに配布可能な形にしたことで、大規模展開が実現した。

最も目を引く成果は、ScalaからJavaへの10,000行のコード移行だ。手作業なら10週間と見積もられていたこのプロジェクトを、あるチームは4日で完了させた。この移行により新しいJDKバージョンへのアップグレードが可能になり、パフォーマンス改善に道が開けた。

Stripeは社内でClaude Codeを「自律的ツール」ではなく「文脈を必要とする新人エンジニア」と位置づけ、そのメンタルモデルで再教育を行ったという。このフレーミングは、AIツール導入時の社内コミュニケーションとして参考になる。

[Stripe Customer Story](https://claude.com/customers/stripe)

## 前提知識ゼロでプロジェクト途中参画、TVerのiOSエンジニアが3つのスキルで乗り切った話

TVerのiOSエンジニア・福島氏は、プロジェクト固有の仕様をほとんど把握しないまま、大規模プロジェクトのバグ修正フェーズに途中参画した。限られたリリース期間で成果を出すため、Claude Codeで3つのカスタムスキルを構築した。

`/analyze-and-create-issues`はQAからのバグ報告を受け取り、ソースコードを調査し、Androidの実装まで横断的に比較して、修正方針をまとめたIssueを自動作成する。`/implement-issue`はそのIssueに基づいて実装を行い、既存アーキテクチャに準拠したコードを書いてビルド確認まで済ませる。`/create-pr`は変更内容を整理し、プラットフォーム間の実装比較表を含むPRを作成する。

ポイントは、AIが「対話形式」で補足情報を段階的に質問してくること。実装ファイルのパス、参照すべきAndroid実装など、必要な情報を自ら引き出しながら精度を上げていく。スキルによって作業手順が標準化されるため、プロジェクト背景を知らなくても一定品質のアウトプットが出せる——途中参画メンバーのオンボーディング問題への一つの解答だ。

[TVer Tech Blog](https://techblog.tver.co.jp/entry/claude-code-use)

## 寝ている間に開発が進む、GMOエンジニアが作ったGoツール「Sleepship」

GMOペパボのエンジニア・dai氏が開発したSleepshipは、タスクファイルを渡すとClaude Codeを自動制御して開発を進めるGoツールだ。名前の通り「寝ている間に開発タスクが完了している」ことを目指している。

仕組みはシンプルで、Markdownで書いたタスクファイルを読み込み、exec.Commandでsubprocessとして実行する。失敗時は自動リトライし、前回のエラー分析を次のプロンプトに組み込む。タスクの再帰的生成にも対応しており、「調査→計画→実装」のような段階的ワークフローを事前定義なしで実行できる。

開発動機は「毎回手動でプロンプト入力するの面倒だな」という素朴なもの。`.sleepship/history.json`に実行履歴が残るため、朝起きて何が行われたか確認できる。Claude Code Routinesがクラウド側のソリューションなら、こちらはローカル環境での自律実行ソリューションと言える。

[GMO Developers Blog](https://developers.gmo.jp/technology/77942/)

## 非エンジニアのCPOが作った「地味だけど毎日使う」11個の自動化

アソビューCPOの横峯氏は、派手なデモ向けのアプリ開発ではなく、日常業務で実際に機能する自動化を11個構築した。共通するのは「毎朝7時に勝手に動き出して、起床後のSlack確認時には結果が準備できている」という設計思想だ。

記事で強調されているのは「デモ映えする一発芸と、業務に定着する仕組みは別物」という視点。生成AIの事例は派手なものに偏りがちだが、本当に価値があるのは毎日淡々と動く仕組みだと指摘する。

具体的な自動化の内容は記事で詳述されているが、ポイントは非エンジニアでもClaude Codeを使えば実用的な自動化を組めること、そしてSlack連携と定時実行を組み合わせることで「能動的に使う」から「勝手に動いている」へシフトできることだ。YOMIKO的には、定例レポートや社内通知系の自動化で同じパターンが使えそうだ。

## Claude Codeとの会話だけでPolymarket自動取引システムを構築、初期ROI 9.6%

Örvar Karlsson氏は、Claude Codeとの単一の会話を通じて、Polymarket（予測市場プラットフォーム）向けの完全な自動取引システムを構築した。価格監視、裁定スキャン、取引実行、学習ループまでを備えている。

構築は段階的に進んだ。まずPolymarketのRust CLIをPythonでラップし、`search_markets("bitcoin")`のような形で呼び出せるようにした。次に5分ごとの価格監視、複数結果市場での裁定機会検出を実装。初回スキャンで182の裁定機会を特定し、バーモント州知事選では43%のROIが得られることを発見した。

取引には1回$20、1日$50のガードレールを設け、すべての取引をJSONLで記録。8件の取引解決で75%の勝率、$148.60の投資に対して+$14.22の利益（9.6% ROI）を達成した。著者の結論は「退屈な戦略が最良の結果をもたらす」——派手なAIトレードではなく、堅実な裁定狙いが功を奏した。

[Medium - Örvar Karlsson](https://medium.com/@rvarkarlsson/building-an-automated-polymarket-trading-system-with-claude-code-1982ff60cc74)

## Telegramからプルリクエストまで、OpenClawが実現する「どこからでも開発」

OpenClawは、WhatsApp・Telegram・Discordなどのチャットアプリから操作できるパーソナルAIアシスタントだ。メッセージを送るだけで、メール管理やカレンダー操作、Webブラウジング、シェルコマンド実行などを実行する。

興味深いのは、OpenClawをClaude Codeと連携させている開発者たちの使い方だ。Sentryからエラー通知を受け取り、OpenClawが自動でテストを実行し、問題を特定してPRを作成する——これをTelegramのチャットから行う。外出先のスマホからバグ修正が完了するワークフローだ。

毎日のブリーフィング生成、Gmail・Calendar・WordPressの統合管理、音声コマンドでのタスク実行なども報告されている。Claude Code単体ではターミナルに縛られるが、OpenClawを組み合わせることで「いつでもどこでも」の操作が可能になる。モバイルファーストで働く人にとっては検討に値するスタックだ。

[OpenClaw](https://openclaw.ai/)
