# Claude Code 今日の発見 — 2026-04-30

AIエージェントが「やりとり」するようになった。今日見つけた事例の共通点は、Claudeが単なるコード生成ツールではなく、交渉し、判断し、失敗から学ぶ存在になりつつあること。

---

## AnthropicがClaude同士に値段交渉させたら、19個のピンポン球を買ってきた

Anthropicが社内で実施した「Project Deal」という実験が興味深い。サンフランシスコのオフィスで、186件・総額4,000ドル超の取引をClaude同士に任せた。人間は最初に「こういうものが欲しい」と伝えるだけ。あとはClaudeが相手のClaudeと交渉し、価格を決め、取引を成立させる。

結果として見えてきたのは、モデル性能の差がそのまま取引結果に反映されること。Opus同士なら拮抗するが、OpusとHaikuが交渉すると、同じ自転車でも38ドルの価格差が生まれた。驚くのは、取引を依頼した人間側がこの格差に気づかなかったこと。そして「礼儀正しいClaude」のほうが攻撃的なペルソナより良い結果を出した。

一番笑ったのは、あるエージェントが「スキーが好き」という一言を拾って、本人がすでに持っているのと同じスノーボードを買ってきたこと。別のエージェントは19個のピンポン球を購入。AIエージェント経済の実験としては示唆に富むが、まだ「任せきり」は早いという結論だった。広告運用の自動入札を複数AIに委ねたらどうなるか、というシミュレーションに応用できそう。

## QAエンジニアがテスト時間を105分から27分に縮めた話

エムスリーのQAチームが半年かけてClaude Codeを導入し、E2Eテストの実行時間を74%削減した事例。技術的なアプローチは地味だが再現性が高い。

まず、固定で3秒待っていた処理を`waitForResponse()`や`waitForLoadState()`に置き換えた。ページが読み込まれた瞬間に次へ進めるようにしただけで、積み上がると大きな差になる。次に、UIの変更に強いPage Objectパターンを導入。最後に、SaaS制約で並列数が限られていた環境からPlaywrightへ移行し、ワーカー数を自由に設定できるようにした。

注目すべきは、MCP（Model Context Protocol）を使って「テスト実行→結果分析→Confluence更新→JIRAチケット作成」を1コマンドに統合したこと。半年で67本のPRがマージされ、後半3ヶ月は前半の3倍以上のペースで改善が進んだという。過去のドキュメント蓄積がAI活用の土台になる、という指摘は他のチームにも当てはまる。

[エムスリーテックブログ](https://www.m3tech.blog/entry/2026/04/20/090035)

## Claudeにコードを書かせてツールを呼ばせる「Programmatic Tool Calling」

Anthropicが4月に発表した新機能の中で、実務インパクトが大きそうなのがProgrammatic Tool Calling。従来、Claudeがツールを使うときは「1回呼んで結果を受け取り、また1回呼んで…」という逐次処理だった。新機能では、Claudeが「複数のツールを並列で呼び、結果をフィルタリングして、必要な情報だけをコンテキストに入れる」コードを自分で書く。

具体例として挙げられていたのは、経費精算の監査。従来の方法だと2,000件以上の経費明細がすべてコンテキストに入り、50KB超のトークンを消費していた。新方式では、ClaudeがPythonで`asyncio.gather()`を使った並列処理コードを書き、予算超過した2〜3名の情報だけを返す。トークン消費は37%減、精度も46.5%→51.2%に改善したという。

広告レポートの集計や、複数キャンペーンの横断分析で同じパターンが使えそう。APIコストを気にしていた案件で試す価値がある。

[Anthropic Engineering Blog](https://www.anthropic.com/engineering/advanced-tool-use)

## 500行のTypeScriptでOpenClaw風の自律エージェントを作った人

OpenClawはAIエージェントが目標に向かって自律的に動き続けるフレームワークとして注目されているが、Claude Code上で同様の仕組みを再現した「ClaudeClaw」というプロジェクトが公開された。ゲートウェイ層はわずか500行のTypeScriptで、セッション管理とメッセージルーティングを担う。

仕組みとしては、SlackやDiscordからメッセージが来ると、ゲートウェイが`claude -p`をヘッドレスで起動し、会話を継続する。チャンネルごとに使えるツールを制限できるので、「コードレビュー用チャンネルではRead/Grepだけ許可、Bash/Writeは禁止」といった運用が可能。複数のサブエージェント（調査担当、コード担当、コミュニケーション担当など）を協調させるマルチエージェント構成にも対応している。

OpenClawがモデル非依存なのに対し、ClaudeClawはClaude専用だがコード実行やGit操作がネイティブで使える。社内ツール連携の実験台として面白い。

## 顧客オンボーディングが5日から2時間になった企業向けユースケース10選

Claude Managed Agentsのパブリックベータが4月8日に始まり、エンタープライズ向けのユースケース集が公開された。いくつかピックアップすると：

顧客オンボーディングでは、KYC確認・アカウント発行・インテグレーション設定・連絡まで一気通貫で自動化し、従来2〜5日かかっていた工程を2時間以内に短縮。法務チームの契約書処理では、分類・エンティティ抽出・リスク条項の検出・ルーティングを自動化し、1文書あたり45分→3分に。承認プロセスの自動化では、ポリシーに基づくルーティングとSLA超過時のエスカレーションで、平均承認日数が12日→3.2日に縮んだという。

面白いのは「継続監視とアラート」のユースケース。ベースラインを学習して誤検知を70〜80%削減しつつ、閾値ベースでは見逃す微妙な異常を検出するという。広告運用のアノマリ検知に応用できそうな発想。

## 3日間寝かせておけるClaude Codeの隠し機能

Qiitaで公開された「Claude Code作成者が明かす隠れた便利機能15選」が実用的だった。特に目を引いたのは`/loop`と`/schedule`コマンド。

`/loop`はローカルで最大3日間、指定間隔で処理を繰り返す。`/schedule`はリモートで最大1週間の定期実行。つまり「毎朝7時にSlackの未読を整理」「PRがStaleになったら自動でリマインド」といった仕組みが、外部ツールなしで組める。

他にも、`/branch`で会話を分岐させて実験したり、`/btw`でタスクを中断せずにサイドクエリを投げたり、`/batch`で数百のエージェントに大規模変更を分散処理させたり。`--bare`オプションで起動を10倍高速化できるのはCI/CD組み込みで役立つ。Chrome拡張で生成コードをその場でプレビューできる機能も、フロントエンド案件では重宝しそう。

## GitHub Actionsに組み込めるClaude Code公式アクション

anthropics/claude-code-actionが公開されており、PRやIssueに対してClaude Codeを自動実行できる。ワークフローのコンテキストを見て「このPRには起動すべきか」を判断する仕組みも入っている。

Sentryは既にこれを使い、自律的にパッチを作成してPRを送るエージェントを本番運用しているという。コードレビューの自動化から一歩進んで「指摘して終わり」ではなく「直してPRまで出す」ところまで来ている。レビュー待ち渋滞が起きているチームには刺さりそう。

[GitHub - anthropics/claude-code-action](https://github.com/anthropics/claude-code-action)
