# Claude Code 今日の発見 — 2026-05-11

「一人で回す」という言葉の意味が変わり始めている。3-4ヶ月かかるデータ基盤構築を1ヶ月でやる情シス部長、26個のエージェントを協調させるために試行錯誤する開発者。AIとの協働は「楽になる」ではなく「できることが増える」フェーズに入った。

---

## 情シス部長がデータ基盤を一人で構築している

ある企業の情シス部長が、Microsoft FabricとClaude Codeを組み合わせて、レガシーなPower BI基盤を一人でモダナイズしている。通常なら2人で3-4ヶ月かかる作業を、1ヶ月未満で回しているという。

仕組みの核心は2つのMCPサーバーの使い分けにある。Fabric MCP ServerがLakehouse、Notebooks、Pipelinesといったデータインフラ層を担当し、Power BI Modeling MCP ServerがテーブルやDAX式といったセマンティック層を担当する。この分離により「データ取り込み→加工→モデリング→デプロイ」が単一のAIセッション内で完結する。1日に5-8件の作業項目を処理できるようになり、従来のGUIベースの10倍の効率だという。

印象的なのは「人間は要件定義と最終確認だけ」という割り切りだ。実装・テスト・デプロイはすべてAIに任せる。広告運用のレポート基盤やクライアントダッシュボードの構築にも応用できそうな構成。

## 26個のエージェントを協調させる試行錯誤

ある開発者が、26個のサブエージェントを並行稼働させようとして「コンテキスト忘却問題」にぶつかった話を公開している。エージェント同士が互いの進捗を参照せず、同じ作業を重複して行ってしまう。

最初の解決策は`.claude/reports/`にメモリプロトコルを置くことだった。各エージェントがここを参照して既存の作業を確認する設計だが、プロトコルは時々無視され、実行速度も落ちた。

最終的にたどり着いたのは「メインエージェントが全コンテキストを握り、各サブエージェントに必要な情報だけを渡す」という中央集権型の構造だった。エージェント数を26個から22個に削減し、スタイルガイドやデザインシステムはSkillsに変換。結果、コンテキストが持続する時間は15-20分から2時間以上に伸び、エージェント定義のコード量は73%削減された。

「分散より集約」という結論は直感に反するが、現時点のAIエージェントの能力を考えると納得できる。

## Markdownを保存するたびに「ファンシーHTML」が生成される

Claude Codeのhook機能を使って、Markdownファイルを保存するたびに自動でインフォグラフィック風のHTMLを生成する仕組みを作った人がいる。PostToolUse hookで`Write`や`Edit`を検知し、`.md`ファイルだった場合に処理が走る。

面白いのは「親プロセスの作業を邪魔しない」設計だ。HTMLへの変換は別プロセスの`claude -p`をバックグラウンドで起動して行う。SVGグラデーション、CSSアニメーション、外部リソース参照なしという制約をプロンプトで指定し、完全にスタンドアロンで動くHTMLを出力させる。`--tools ""`オプションで子プロセスの暴走も防いでいる。

設計ドキュメントやプランファイルなど「低頻度だがレビュー価値が高いコンテンツ」向きで、ブログ執筆のような頻繁な保存には向かないと注意書きがある。クライアント向け資料のビジュアル化に使えそうなアイデア。

## Claude Codeのソースコードが流出し、再実装競争が始まった

3月31日午前4時半、セキュリティ研究者がnpmパッケージ内に約60MBのソースマップファイルを発見した。Claude Codeの内部実装51万行が、数時間で拡散した。Anthropicが削除した時点では、すでに数万のGitHubフォークが存在していた。

流出したのは「ハーネス」と呼ばれる部分で、モデルへの指示、ツール呼び出し、挙動の組み立て方を規定するコアロジックだ。競合他社やスタートアップにとっては「Claude Codeの機能を複製するためのロードマップ」を手に入れたに等しい。実際、「Claw-Code」など複数の再実装プロジェクトが立ち上がった。

Anthropicは「顧客データや認証情報は含まれていない」と説明しているが、エージェントの設計パターンが公開されたことの影響は大きい。オープンソースのエージェントフレームワーク開発が加速する可能性がある。

[Impress Cloud Watch](https://cloud.watch.impress.co.jp/docs/column/techwatch/2101100.html)

## OpenClawはClaude Codeを「部品」として使う

Peter Steinberger氏が開発した「OpenClaw」というツールがある。WhatsApp、Telegram、Discord、Slackなど複数のチャットアプリから操作できるパーソナルAIアシスタントで、ローカルで動作する。

Claude CodeやCodexのセッションを上位レイヤーから統括できるのが特徴だ。「Claude Code / Codexのセッションをどこからでもキックオフできる」という使い方が報告されている。つまり、コーディング作業はClaude Codeに任せつつ、メール処理、カレンダー管理、スマートホーム制御、フライトチェックインなど50以上のサービス連携はOpenClawが担う、という役割分担になる。

Sentry経由でエラーを拾い、自律的にテストを実行してPRを作成する、という完全自動ループを回しているユーザーもいる。Claude Codeを「一つのツール」として組み込むアーキテクチャは、今後の主流になりそうだ。

[OpenClaw公式](https://openclaw.ai/)

## 2,300スターのワークフローエディタ

「Claude Code Workflow Studio」というVSCode拡張が注目を集めている。ノードとコネクタをドラッグ＆ドロップで配置し、AIワークフローを視覚的に設計できる。

実用例としては、GitHubからコードを取得→単体テスト実行→レポート生成という基本フローから、テスト失敗時にSlackへ分岐するといった条件分岐まで対応する。設計したワークフローはエクスポートしてそのまま実行可能だ。

プログラミングなしでエージェントの動きを設計できるため、業務フローの自動化をエンジニア以外が主導するケースに向いている。マーケティング施策の自動化フローを非エンジニアが設計し、エンジニアがレビューする、という分業が現実的になる。

## 185個のエージェントを束ねるプラグイン集

wshobson氏のGitHubリポジトリ「agents」が、Claude Codeのプラグインエコシステムの規模感を示している。185個の専門エージェント、16個のマルチエージェントオーケストレーター、153個のスキル、100個のコマンドが80個のプラグインに整理されている。

単独で使うというより「必要な部品を選んで組み合わせる」ためのカタログだ。セキュリティレビュー、テスト生成、ドキュメント作成など、用途別に分類されている。プロダクション向けのオーケストレーションパターンも含まれており、自社のワークフローを構築する際の参考になる。

[GitHub - wshobson/agents](https://github.com/wshobson/agents)
